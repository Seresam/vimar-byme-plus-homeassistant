Add alternative "attach" auth flow (username/useruid/password)

Support an alternative authentication path that accepts username, useruid and password instead of the setup code. The config flow accepts optional username/useruid/password and passes an in-memory UserCredentials object through Coordinator -> VimarClient -> AssociationService; persistence to the per-gateway DB is centralized in AssociationService. Attach payload now uses clientinfo {clienttag:"userapp", manufacturertag:"Vimar", lang:"it"} when the username looks like an email.
